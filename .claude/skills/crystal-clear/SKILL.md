# Crystal Clear — Alistair Cockburn

Livro-fonte: `LivrosDev/Crystal Clear - A Human-Powered Methodology for Small Teams - Autor (Alistair Cockburn).pdf`

## Ideia central
Processo leve, **movido a pessoas**, para times de 2–8 pessoas na mesma sala. Busca **segurança** de que o projeto terminará bem, com a menor cerimônia possível.

## As 7 propriedades
1. **Entrega frequente** (a usuários reais, a cada poucos meses no máximo).
2. **Melhoria reflexiva** (workshops de reflexão periódicos).
3. **Comunicação osmótica** (informação flui pelo ambiente — mesma sala).
4. Segurança pessoal (falar sem medo).
5. Foco (prioridades claras e tempo sem interrupções).
6. Acesso fácil a usuários especialistas.
7. Ambiente técnico com testes automatizados, gestão de configuração e integração frequente.
(As três primeiras são obrigatórias; quanto mais das outras, mais "no zona segura".)

## Estratégias e técnicas
- **Exploração de 360°**, **vitória antecipada**, **esqueleto ambulante** (walking skeleton), **re-arquitetura incremental**, **radiadores de informação**.
- Técnicas: oficina de metodologia, planejamento "blitz", estimativa Delphi, daily stand-ups, design essencial de interação, miniatura do processo, programação lado a lado, gráficos de burn.

## Processo e produtos
- Ciclos aninhados: projeto → entrega → iteração → semana/dia → episódio de integração.
- Produtos de trabalho leves: declaração de missão, lista de atores-objetivos, casos de uso, mapa de releases, status de risco etc.

## Erros comuns
- Achar que "leve" = sem disciplina; pular reflexão; não entregar a usuários reais.

## Diagnóstico rápido
- [ ] Entregamos algo útil a usuários nos últimos 3 meses?
- [ ] Fizemos uma reflexão de melhoria no último mês?
- [ ] Um dev escuta naturalmente as conversas relevantes?
- [ ] Alguém tem medo de dar más notícias?
