# Extreme Programming Explained — Kent Beck

Livro-fonte: `LivrosDev/Extreme Programming Explained - Embrace Change - Autor (Kent Beck).pdf` (edição em alemão)

## O problema
- **Risco** é o problema básico: atrasos, projeto cancelado, sistema azedando, alta taxa de defeitos, negócio mal compreendido, mudança no negócio, excesso de funcionalidades, rotatividade.
- **Economia:** software tem valor de **opções**; adiar decisões e entregar cedo maximiza valor.
- **Quatro variáveis:** custo, tempo, qualidade, escopo — deixe o **escopo** variar.
- Se o **custo de mudança** for mantido baixo (testes, design simples, refatoração), mudar tarde é barato. "Aprender a dirigir": pequenas correções contínuas.

## Valores
**Comunicação, simplicidade, feedback, coragem** (respeito na 2ª edição).

## Princípios básicos
Feedback rápido, assumir simplicidade, mudança incremental, abraçar a mudança, trabalho de qualidade; secundários: ensinar a aprender, investimento inicial pequeno, jogar para ganhar, experimentos concretos, comunicação aberta, trabalhar com os instintos, responsabilidade aceita, adaptação local, viajar leve, medição honesta.

## Atividades básicas
Codificar, testar, ouvir, projetar.

## As 12 práticas
1. **Jogo do planejamento** (negócio decide escopo/prioridade, técnico estima).
2. **Pequenas releases.**
3. **Metáfora** do sistema.
4. **Design simples** (passa nos testes, sem duplicação, expressa intenção, mínimo de classes/métodos).
5. **Testes** (unitários pelos devs, funcionais pelo cliente).
6. **Refatoração.**
7. **Programação em par.**
8. **Propriedade coletiva** do código.
9. **Integração contínua.**
10. **Semana de 40 horas** (ritmo sustentável).
11. **Cliente no local.**
12. **Padrões de codificação.**
As práticas se apoiam mutuamente — os pontos fracos de uma são cobertos pelas outras.

## Gestão e adoção
Papéis (programador, cliente, testador, rastreador, coach, consultor, chefe); adote uma prática por vez, começando pelo problema mais doloroso; saiba quando XP não serve (cultura hostil, times grandes demais, feedback lento).
