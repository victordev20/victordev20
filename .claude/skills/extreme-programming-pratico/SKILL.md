# eXtreme Programming — Práticas para o Dia a Dia (Casa do Código)

Livro-fonte: `LivrosDev/eXtreme Programming - Práticas para o dia a dia no desenvolvimento ágil de software - Autor (Casa do Código).pdf`

## Por que projetos falham
Cliente distante · "cereja do bolo" (funcionalidades desnecessárias) · testes no final · trabalho empurrado (push) · **dívidas técnicas**.

## Métodos ágeis
Manifesto Ágil · **Lean Software Development** (eliminar desperdício, amplificar aprendizado, decidir tarde, entregar rápido, empoderar o time, integridade, ver o todo) · Scrum · XP.

## Valores do XP
**Comunicação · Feedback · Simplicidade · Coragem · Respeito.**

## Papéis
Desenvolvedor · Cliente · **Coach** · Testador · **Cleaner** (cuida da limpeza do código) · **Tracker** (acompanha métricas) · Gerente · outros.

## Time coeso
Multidisciplinar, auto-organizável, sentado junto, área de trabalho informativa (quadros, gráficos).

## Práticas
- **Planejamento:** jogo do planejamento, **histórias de usuário**, estimativas, **pequenas entregas**, iterações curtas, cliente presente.
- **Código:** **TDD**, **refatoração**, design simples, **programação em par**, **propriedade coletiva**, **padrões de codificação**, metáfora.
- **Integração:** **integração contínua**, build de 10 minutos.
- **Ritmo sustentável** (sem horas extras crônicas).
- **Reuniões:** stand-up, retrospectivas.

## Como começar (sugestão do livro)
1. Escolha a dor mais forte do time.
2. Adote a prática que a ataca (ex.: bugs → TDD; integração dolorosa → CI).
3. Meça antes/depois; retrospectiva; adicione a próxima prática.

## Checklist semanal
- [ ] Pareamos em código crítico?
- [ ] Todo código novo tem teste?
- [ ] A build ficou verde a maior parte do tempo?
- [ ] Entregamos algo ao cliente nesta iteração?
